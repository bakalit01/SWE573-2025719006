## What the AI was used for
- **Planning:** the 10-week project plan, requirements, user stories with acceptance criteria, and their delivery order (`docs/`)
- **GitHub set-up:** issue and pull request templates, labels and milestones, creating the backlog issues, and the CI, release, issue-seeding and screenshot workflows (`.github/`, `scripts/`)
- **Code:** the Django application (`accounts/`, `communities/`, `crafts/`, `config/`), templates, CSS and JavaScript, and the automated tests (`tests/`)
- **Content:** collecting the 17 real craft examples from public sources (museums, encyclopedias, Wikimedia Commons) with their sources and photo credits (`crafts/reference_data.py`)
- **Documentation and presentations:** README, changelog, design notes and screenshots, ADR, and the progress presentation slides
- **Feedback rounds:** turning instructor and user feedback (FB-01 to FB-08) into issues and changes

## How it was used
- The author set the goals, scope and priorities, gave feedback on each version, and decided what to keep.
- The AI wrote drafts of code and documents, ran the tests and checks, and opened pull requests. Every change went through a pull request, and automated tests (CI) ran on each one.
- Commits made with the AI's help carry the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`, so they can be identified in the Git history.

## Responsibility
The author is responsible for the submitted work, including its accuracy and how Indigenous cultural content is presented. Content about real communities comes from cited public sources, and every craft page has a link for reporting errors or asking for removal.
